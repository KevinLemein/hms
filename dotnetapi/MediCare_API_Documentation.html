1. Overview

The MediCare REST API is the backend data service for the MediCare healthcare management system. It provides full CRUD (Create, Read, Update, Delete) operations for all core entities including patients, doctors, appointments, medical records, prescriptions, payments, and supporting lookup data.

The API is built with ASP.NET Core 10, uses Entity Framework Core for database access, and connects to a PostgreSQL database. All responses are JSON-encoded.

3. Authentication

All controllers are currently decorated with [AllowAnonymous]. No authentication token is required for any endpoint in the current version.

Administrator Note: It is strongly recommended to enable authentication (e.g., JWT Bearer tokens) before deploying to a production environment. The User model includes Role and Password fields intended for future role-based access control.

7. API Endpoints

7.1 Users

Manages system user accounts (administrators, doctors, receptionists, etc.).

GET  /api/Users

Returns a list of all users in the system.

Response Body (200 OK) — Array of User objects

[
  {
    "id": 1,
    "firstName": "John",
    "lastName": "Doe",
    "email": "john.doe@medicare.com",
    "username": "johndoe",
    "role": "Admin",
    "enabled": true,
    "createdAt": "2026-04-06T15:25:37",
    "updatedAt": null
  }
]

GET  /api/Users/{id}

Returns a single user by ID.

ParameterTypeLocationDescription
idintURL pathThe unique user ID

Responses: 200 OK with user object  |  404 Not Found

POST  /api/Users

Creates a new user account.

Request Body

{
  "firstName": "Jane",
  "lastName": "Smith",
  "email": "jane.smith@medicare.com",
  "username": "janesmith",
  "password": "SecurePassword123",
  "role": "Receptionist",
  "enabled": true
}

Responses: 201 Created with new user object

PUT  /api/Users/{id}

Updates an existing user. The id in the URL must match the id in the request body.

ParameterTypeLocationDescription
idintURL pathThe unique user ID

Responses: 204 No Content  |  400 Bad Request  |  404 Not Found

DELETE  /api/Users/{id}

Permanently deletes a user account.

Responses: 204 No Content  |  404 Not Found

7.3 Doctors

Manages doctor profiles. A doctor is linked to a User account and optionally assigned a medical speciality.

GET  /api/Doctors

Returns a summarised list of all doctors (includes name and speciality from related records).

Response Body (200 OK) — Array of DoctorVm objects

[
  {
    "id": 1,
    "userId": 3,
    "firstName": "James",
    "lastName": "Mwangi",

    "speciality": "Cardiology",
    "isAvailable": true,
    "createdOn": "2026-04-06T16:00:00",
    "createdById": 1
  }
]

GET  /api/Doctors/{id}

Returns the raw Doctor entity (includes foreign key IDs only; no joined names).

Responses: 200 OK with Doctor object  |  404 Not Found

POST  /api/Doctors

Creates a new doctor profile. The referenced userId must already exist.

Request Body

{
  "userId": 5,
  "specialityId": 1,

  "createdOn": "2026-04-22T00:00:00",

DELETE  /api/Doctors/{id}

Deletes a doctor profile.

Responses: 204 No Content  |  404 Not Found

7.4 Appointments

Central entity for scheduling. Appointments link a patient to a doctor at a specific date/time. Retrieving a single appointment also returns the associated medical record and prescriptions.

GET  /api/Appointments

Returns a flat list of all appointments with doctor name, patient name, and status label resolved.

Response Body (200 OK) — Array of AppointmentsVm

[
  {
    "id": 1,
    "doctorId": 1,
    "doctor": "James",
    "patientId": 2,
    "patient": "Kamau Peter Njoroge",
    "appointmentDateTime": "2026-04-25T09:00:00",
    "statusId": 1,
    "status": "Scheduled",
    "code": 0,
    "message": null,
    "error": null
  }
]

GET  /api/Appointments/{id}

Returns full appointment details, including the medical record and all prescriptions linked to that appointment.

    {
      "id": 8,
      "appointmentId": 1,
